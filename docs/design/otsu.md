# 当帧 Otsu 自动阈值

输入仍是一张 256×256×8-bit 原图；去噪后的像素先进入
`otsu_frame_buffer` 的 64 KiB 帧缓存，同时统计直方图。最后一个像素握手后，
暂停接收下一帧，算出本帧阈值，再从 BRAM 回放本帧进行分割与轮廓提取。
因此一次上传即可得到使用当前图片自动阈值的处理结果，不需要 PC 再发一次预热帧。

`otsu_core` 每次计算结束后用 256 拍清空直方图；清零、计算期间 `ready=0`。
有效帧末条件为 `ready && en && valid_in && frame_done`。
统计总数、灰度总和随握手累积，包含最后一个像素；计算期间直方图保持不变。
每帧最多 65536 像素，计数器使用 17 位。

评分比较的是标准类间方差。设背景为灰度 ≤t、前景为灰度 >t，
`D = total_sum*w0 - sum0*total_count`，忽略对所有候选相同的总像素数平方后，
比较 `D²/(w0*w1)`。用精确交叉乘法比较候选分数，选取第一个最大值，
不使用旧版的绝对差近似，也不使用截断除法。
矩为 41 位、平方为 82 位、交叉乘积为 116 位，足以容纳 65536 像素的全部范围。
平方和交叉乘法复用移位加法数据通路，避免大规模组合除法器或乘法器。
最密集的 256 灰度直方图计算约 29004 拍，在 25.2 MHz 下约 1.15 ms；
另加输入缓存和回放时间，不影响网口现有的完成确认协议。

自动分割使用 `pixel > otsu_threshold`。单一灰度帧返回该灰度，得到全背景掩膜，
包括全黑、全白；手动模式继续使用原来的 `pixel >= manual_threshold`。
模式和手动阈值在首个输入像素握手时锁存，回放期间修改寄存器只影响下一帧。
手动帧仍计算 Otsu 供切回自动时查询；自动回放始终等待当前帧计算结果。
输出最后一个像素被下游接收后才允许缓存下一帧，防止轮廓补尾时覆盖缓存。

`STATUS`（字节偏移 0x0C）表示实际阈值，`DATA_REG`（0x80）是手动配置值。
GUI 处理结果区域使用 `actual_threshold` 显示 STATUS，自动模式不会误显示手动配置。

验证命令：

```bash
python scripts/tests/run_otsu_checks.py --synth
python scripts/tests/run_display_checks.py
python -m unittest discover -s network/host -p 'test_*.py'
```

新测试覆盖八组完整帧与精确有理数参考、连续帧、全黑/全白、相邻灰度、随机分布、
有效帧末握手、当帧回放、反压保持、手动比较边界及中途改配置。
局部综合报告位于 `build/tests/otsu/utilization.rpt`，同时检查帧缓存推断为 BRAM。

RTL 有变更，需要重新生成并下载位流；GUI 服务重启后使用新的阈值回读逻辑。
