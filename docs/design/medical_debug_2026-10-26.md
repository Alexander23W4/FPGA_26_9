# 医学模式输出与耗时排查（2026-10-26）

## 板端已取得的证据

使用完整原始 FP32 U-Net；图像为 `Site_G_20/patient-2-4/000000.bin`。

- 旧位流单帧 27.7405 s；PS 计时 PL→DDR 27710.765 ms，PC 收图 4.355 ms。该次慢主要发生在 PL 推理和访存，不能归因于 GUI PNG 或网口传输。
- 干净重启后的第一帧：U-Net 归一化输入逐像素等于发送图；DDR logits 与独立软件最大误差约 8.35e-6，类别无差异。五类数量为 `[61359, 775, 1259, 922, 1221]`。
- 同一帧最终 RGBA 仅 49 个黄色像素，其中 46 个在分类背景位置。医学统计也只报告 RA 有目标。因此分类之后确实存在异常，不能把画面坏全部归咎于模型或类别名称。
- 干净重启前另一次现场：配准输入向上偏移约 60 像素；模型对实际偏移输入仍计算正确。旧配准逐帧累加中心 ROI 位移，可能把局部心肌运动积累为整幅图漂移，序列切换时又未重建参考。
- 原输出算法独立 256×256 C/RTL 联合仿真通过；这不能证明旧位流的完整集成链路正确。旧位流异常的最终根因尚未在本地完全复现。

现场文件保存在 `build/unet/debug/`：`board_result.json`、`board_output.rgba`、`features_input.f32`、`features_logits.f32`、`features_labels.f32`。这些是本机调试数据，不纳入源码。

## 当前改动

1. 医学模式增加“显示轮廓 / 显示掩膜”，分别发送现有 VIDEO_MODE=1 / 3；HDMI 和 PC 共用着色规则。轮廓模式只画彩色轮廓；掩膜模式只按透明度叠加区域，不再强制把轮廓混入。
2. 医学连续流最多派发一次推理；Python 待发队列仍可预读。停止立即清空待发输入，绕过正在等待长帧的 pause 控制；已进入 PL 的当前帧安全收尾。图像处理模式仍保留原来的多帧流水能力。这里没有实现运行中强制复位推理核心，所以停止不是硬件立即中止。
3. DDR 配准改为以本序列首帧中心 ROI 为固定参考，搜索 ±8 像素的绝对位移，不再累计局部位移。PS 在新序列、循环回到首帧及单图任务开始前重建医学模式 epoch；只在没有活动 DMA 时切换。
4. 完整网络保留 FP32、78 个操作、全部原权重和类别映射。空间 tile 32→64；把边界判断移到连续通道访存循环外，HLS 已识别输入特征突发读和结果突发写。数值对比不改变类别。
5. 输出类别由 argmax 直接送三行缓存，移除“整数类别→DDR 浮点副本→重新读回→整数类别”的输出依赖。DDR 类别副本保留用于诊断。此改动简化了可疑输出段，但在新位流验证前不能宣称已证明解决旧板上的 49 黄点。

## 新版耗时的分析估计（非板测）

按 78 个操作、16 并行通道、80 MHz、64 像素 tile 计数：

- 217812480 个 DOT 循环周期，约 2.723 秒，已计入下面合计，不再重复加算。
- 54453120 个权重读字；234619826 个输入特征读字（约 938.5 MB）；13113344 个卷积输出写字。
- 连同初始化，假设每字一拍且没有额外等待，分阶段循环工作量约 6.51 秒；该实现没有把装填与全部 MAC 重构为 DATAFLOW 并行。
- 加入突发建立、循环控制、剩余算子及 DDR 等待，规划估计 8～15 秒/帧，中心约 10 秒；不是实测区间，也不是保证上限。
- 保留完整模型时，10 FPS 要求每秒约 337 亿次有效 MAC。把部分算子移到双核 Cortex-A9 并不会自动减少这项工作量。

Python PS 推理 10～40 秒/帧仍只是未经目标运行库实测的粗估；不能把中心 20 秒视为事实。
