## 0. 先搞清楚：硬件和软件是分开的两件事

```
┌──────────────────────────────────────────────────┐
│  硬件侧（Vivado）       ← 不需要任何 C 代码        │
│                                                   │
│   ./scripts/build.sh zynq -n <平台名>             │
│          ↓                                        │
│     .xsa（硬件描述：地址/时钟/外设哪些开了）        │
│     .bit（PL 位流）                               │
└─────────────────────┬─────────────────────────────┘
                      │  .xsa 是软件侧唯一的输入
                      ▼
┌──────────────────────────────────────────────────┐
│  软件侧（Vitis Unified）  ← 到这一步才需要你的 C   │
│                                                   │
│   建 Platform Component（读 .xsa → 生成 BSP）     │
│          ↓                                        │
│   建 Application Component + 写你的 C             │
│          ↓                                        │
│     .elf                                          │
└──────────────────────────────────────────────────┘
```

**所以第一次跑 `zynq` 命令时，你一行 C 都不用写。**

### 关于 `-n` 后面那个名字

**它只是工程名 / 文件夹名，跟你要做什么应用完全无关。**
叫 `ps_base`、`my_zynq`、`test1` 都行。

**Vivado 工程名** 和 **Vitis 应用名** 是**两个独立的名字**。

### Vitis Unified 的两个入口

| 方式 | 命令 / 操作 |
|---|---|
| **GUI** | 开始菜单 `Vitis 2023.2`，或 `vitis -w <工作区>` |
| **脚本** | `vitis -s <python脚本>` ← **我已按官方 API 写好 `scripts/vitis/build_ps.py`** |
| 交互 shell | `vitis -i` |

> Unified IDE 的脚本接口是 **Python**（`import vitis`），**不是** xsct/Tcl。

# 阶段 2 · PS 应用（这里才写 C）

## 2.1 建 Application Component

**GUI**：`Create Application Component` → 选平台 → Domain 选 `standalone_ps7_cortexa9_0`
→ Template 选 `Empty`

**可用模板**（本机 Vitis 2023.2 **实测**的有效名单）：

```
hello_world         ← 默认，自带 helloworld.c，开箱能编出 ELF
empty_application   ← 空工程，src/ 里什么都没有，要自己写 main.c
dhrystone           memory_tests        peripheral_tests
lwip_echo_server    lwip_tcp_perf_client  lwip_tcp_perf_server
lwip_udp_perf_client  lwip_udp_perf_server
rsa_auth_app        zynq_dram_test      zynq_fsbl
```

> ⚠️ 官方示例代码里写的是 `template = "empty"`，**这个版本里无效**，会报
> `Invalid Template "empty"`。必须用 `empty_application`。

**脚本**：`./scripts/build.sh app -n <应用名>` 会自动建，模板用 `-T` 选：

```bash
./scripts/build.sh app -n <应用名>                        # 默认 hello_world
./scripts/build.sh app -n <应用名> -T empty_application    # 从零开始
```

> **命名约定**：platform 名默认 = **硬件工程名**（也就是 `.xsa` 的文件名），
> 脚本**不额外加任何后缀**。比如硬件工程是 `fpga_26`，应用叫 `MID_plt`：
> ```bash
> ./scripts/build.sh app -n MID_plt
> # -> platform: fpga_26   application: MID_plt
> ```
> 想自己起名就 `-p <平台名>`。
>
> 但 platform 组件和 application 组件在 Vitis 工作区里是**同一层目录**
> （`csrc/<组件名>/`），同名会互相覆盖。所以**两者同名时命令直接报错退出**，
> 脚本绝不会自作主张改名：
> ```bash
> $ ./scripts/build.sh app -n fpga_26
> [ERR ] Platform name and application name are identical: fpga_26
> [FAIL] Refusing to run with colliding component names.
> ```
> 这时你选一个：给平台单独起名 `-p`，或给应用换个名字 `-n`。
>
> **平台已建好会自动复用，不会重编译。** 想强制重编：
> ```bash
> ./scripts/build.sh app -n <应用名> -f
> ```
>
> **多个应用共用同一个平台**（推荐，省得每个应用都建一遍 BSP）：
> ```bash
> ./scripts/build.sh app -n app1 -p fpga_26
> ./scripts/build.sh app -n app2 -p fpga_26
> ```
>
> ⚠️ `all` 命令里 `-n` 同时是工程名和应用名，平台名默认又是工程名 → **必然撞**，
> 所以 `all` **必须显式给 `-p`**：
> ```bash
> ./scripts/build.sh all -n fpga_26 -p hw
> ```

## 2.2 写什么

源码放这里 —— 就是 Vitis 工作区里应用组件的 `src/`：

```
csrc/<应用名>/src/          ← 你写 C 的地方，git 会跟踪
```

```bash
./scripts/build.sh app -n MID_plt      # 建出 csrc/fpga_26/（平台）+ csrc/MID_plt/（应用）
                                        # 默认 hello_world 模板，直接就能编出 MID_plt.elf
```

编出来后你把 `csrc/MID_plt/src/helloworld.c` **换成自己的代码**（或者删掉它，
改用 `-T empty_application` 从零开始）。用 `hello_world` 起手的好处是：
先跑通一遍，确认平台 / BSP / 交叉工具链 / 链接脚本全对，再往里填自己的东西。

> **不需要改 `CMakeLists.txt`。** 它用的是
> `aux_source_directory(${CMAKE_SOURCE_DIR} _sources)`，会**自动收集** `src/`
> 下所有源文件。往里面扔 `.c` / `.cpp` 就行。
>
> **模板**（`-T` 选，默认 `hello_world`）：
>
> | 模板 | 生成的东西 | 什么时候用 |
> |---|---|---|
> | `hello_world` | `helloworld.c` + `platform.c` + `platform.h` | **默认**，开箱就能编出 ELF，先用它验证环境 |
> | `empty_application` | 什么都没有（`src/README.txt` 只写 "Add your own sources"） | 你要从零自己写 `main.c` |
>
> ⚠️ 用 `empty_application` 时**第一次 `build.sh app` 必然失败**，报
> `!!!NO_SOURCES!!!` / `No sources present for the build` —— 因为真的没有源码可编。
> 放进去 `.c` 再跑一次就好。
>
> ⚠️ **只有 `csrc/<应用名>/src/` 入库**。同一组件下的 `build/ export/ hw/
> resources/ _ide/ zynq_fsbl/` 等全是生成物，已被 `.gitignore` 忽略。
> `csrc/` 不在 `build/` 里，所以 `./scripts/build.sh clean` 不会删你的代码。

两个方向：

### 方向 A：用 BSP（实际项目用）
- `#include "xparameters.h"` / `"xil_printf.h"`
- `xil_printf("...")` 直接就能从串口出来（BSP 的 stdout 已指向 `ps7_uart_1`）

### 方向 B：直接戳寄存器（理解硬件，对应你 ysyx 的 AM）

**硬件事实：**

| 项 | 值 | 从哪查 |
|---|---|---|
| UART1 基地址 | `0xE0001000` | `xparameters.h` 的 `XPAR_XUARTPS_0_BASEADDR` |
| UART 参考时钟 | 100 MHz | `ps7_preset.tcl` 的 `UART_PERIPHERAL_FREQMHZ` |
| 串口参数 | 115200 / 8 / N / 1 | 你定 |

**寄存器偏移**（查 `E:\Xilinx\Vitis\2023.2\data\embeddedsw\XilinxProcessorIPLib\drivers\uartps_v3_13\src\xuartps_hw.h`）：

| 寄存器 | 偏移 |
|---|---|
| CR 控制 | `0x00` |
| MR 模式 | `0x04` |
| BAUDGEN | `0x18` |
| BAUDDIV | `0x34` |
| SR 状态 | `0x2C` |
| FIFO | `0x30` |

**波特率**：`参考时钟 / (BAUDGEN × (BAUDDIV + 1))` → 自己凑 115200

**`putch` 逻辑**：SR 的 `TXFULL` 清零前一直等 → 往 FIFO 写一字节

**位定义**：同一份 `xuartps_hw.h` 里查（`CR_RXRST`/`CR_TXRST`/`CR_RX_EN`/`CR_TX_EN`/`MR_PARITY_NONE`/`SR_TXFULL`）

## 2.3 编译下载

**GUI**：组件右键 → Build
**脚本**：`./scripts/build.sh app -n <应用名>`（产物 `.elf` 会归档到 `build/out/...`）

**接线上电**：
1. USB-C 接 PC ↔ 板子 **J2 调试口**（丝印 `HUB / JTAG / UART`）
2. 板子上电
3. `./scripts/build.sh check` 确认认到设备

**检查点**：多出 `USB-Enhanced-SERIAL CH9102 (COMx)` + 一个 JTAG 设备。

> ⚠️ **JTAG 是唯一没验证过的环节。** 芯片丝印 `M02HS2`，非标准型号。
> 认不出来把设备管理器的 VID/PID 发我。

**下载**：Unified IDE 里用 `Run` / 调试器；或 Vivado 的 `Program FPGA` 下 bit。

**看串口**：串口助手打开新 COM 口，**115200 / 8 / N / 1**

# 阶段 3 · RTL（仿真先行）

> PL 侧，和上面 PS 流程**互相独立**，可并行。

## 3.1 写 RTL
你在 `rtl/` 下建模块。**第一个建议写最简的**（LED 闪 / UART 发送），
目的是先跑通工具链，再堆真正的设计。

**工程建议：**
| 建议 | 为什么 |
|---|---|
| 分频/延时系数用 `parameter`，别写死 | 仿真时能覆盖成小值，否则要跑几千万拍 |
| 一个文件一个模块 | 方便复用和单独仿真 |

## 3.2 写约束
你在 `constrs/` 下建 `<工程名>.xdc`。

> `constrs/acz7015/acz7015.xdc` 是**板级全量参考**，查引脚用，**别直接挂到工程上** ——
> 用不到的端口会全部报错。

要写：`create_clock`（50 MHz，接 L5）+ 每个端口的 `PACKAGE_PIN` / `IOSTANDARD`

**引脚号**：查 `constrs/acz7015/pinmap.csv`

## 3.3 写测试平台 + 跑仿真
你在 `sim/tb/` 下建自检式测试平台（`[PASS]`/`[FAIL]` + 超时保险丝）。

```bash
./scripts/build.sh sim -n <工程名> -b <测试平台顶层名>
```

## 3.4 综合出位流
```bash
./scripts/build.sh pl -n <工程名> -t <顶层模块名>
```
**检查点**：`build/out/.../<工程名>.bit` 存在，时序收敛（WNS ≥ 0）。
下载：Vivado → `Program FPGA`

# 阶段 4 · PL + PS 合体

```bash
./scripts/build.sh zynq -n <平台名> -a
```

`-a` 额外生成 `/axi_interconnect_0`、`/rst_ps7_50M`、`/axi_gpio_led`。

**你写 C**：用 `XGpio` 驱动，去 `xparameters.h` 查设备 ID 宏名。

**检查点**：串口打印的同时 LED 跟着变 → **ARM 控制 PL 通了。**

> 要做视频/图像通路（AXI-DMA、VDMA、自定义 IP），就在 BD 里继续加 IP，
> 重新出 `.xsa`，再 `./scripts/build.sh app -n <应用名>`。
