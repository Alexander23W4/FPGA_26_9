# 四腔几何容积估算与 ED/ES 检测

## 当前实现

`medical_accel_top.v` 已实际计算四腔的逐帧几何体积指数，并自动发布 ED/ES 配对结果。
横、纵及估计的离面间距暂按 1 个长度单位处理，**PL 输出单位为 `像素³ × 100`，不是 mL**。

实际计算路径：

```text
输入握手 → 四腔掩膜逐行测宽 → 宽度平方累加 → 四腔逐帧体积指数
                                             ↓
                          LV 容积曲线定位 ED/ES → 同帧四腔快照 → 8 个只读结果
```

- `mask_volume_estimator.v`：计算每帧四腔几何体积。
- `ed_es_tracker.v`：检测 LV 峰谷，锁存同一收缩过程的四腔 ED/ES 值。
- `medical_accel_top.v`：像素/标志直通、实例化计算和时相模块。
- `tests/`：独立 Python 浮点参考、RTL 流水线/反压/时相/AXI 测试，以及 PS 系数换算测试。

原有 `volume_calc.v`、`area_counter.v`、`long_axis_extent.v`、`div_u64_u64.v`、
`medical_axi_lite.v`、`bilinear_interp.v` 不在当前实例化路径中。
GLS 已从当前 RTL 和 PS 接口移除；`medical_metrics_full/` 是未接入的旧资料包。

## 几何模型与精度范围

每行从该腔掩膜的第一个有效像素到最后一个有效像素，取跨度 `w[y]`，空行取 0。
将每行看作厚度 1、直径 `w[y]` 的圆盘：

```text
V_index = π/4 × Σ w[y]²
寄存器值 = round(V_index × 100)
```

RTL 用 `round(π/4 × 100 × 65536) = 5147185` 作定点系数。
宽度平方、行累加、常数乘法和舍入分别流水处理，无除法、无整帧像素缓存。
默认 256×256 全掩膜结果为 `1317679360`；不会出现 65536 像素计数溢出。
0 留给空掩膜，溢出饱和到 `0xFFFFFFFE`，`0xFFFFFFFF` 留给未就绪。

这是单视角、图像纵向切片、圆形横截面的**工程几何代理**，没有完成解剖长轴对齐，
也不等于标准双平面 Simpson 法。四腔当前统一计算这个指数，尤其 RV 不应被当作已验证的
临床三维容积。一个标定系数只能修正尺度，不能消除几何模型误差。
掩膜应表示填充后的单个腔室；同一行多块分离区域会被当作从首到末像素的一整条跨度。
轮廓位只透传，不参与当前容积计算。

## 自动 ED/ES

先以三帧中值滤波后的 LV 体积曲线定位共同的心室时相。中值只用于判断转向，
锁存的仍是窗口中间那一帧的原始四腔数值和原始帧号，不将平滑值当作测量结果。
首尾未形成三帧窗口的点不参与时相判定。

1. 先观察有效的上升段，避免把从收缩中途开始的视频第一帧误认作 ED。
2. 峰值后连续下降达到阈值，确认 ED 候选及其四腔快照。
3. 谷值后连续上升达到阈值，确认 ES，立即同时更新 8 个结果寄存器。
4. 继续寻找下一次收缩，结果可以升高或降低；不累计复位以来的全局最大/最小值。

默认相对转向阈值为 `1/32`（约 3.125%），要求连续 2 帧确认转向，
ED/ES 至少相隔 5 个源视频帧；超过 240 帧仍未配对则重新搜索。
这些都是 `medical_accel_top` 参数，按源视频采样密度调整。
该默认值针对当前 CardiacUDA 序列，不能无条件用于采样密度不同的视频。
尚未确认 ES 时，若出现更高峰，会更新本次 ED 候选，避免将峰前短暂下降拆成一次收缩。
相等峰/谷平台采用平台最后一帧，输出数值来自原始帧快照。
阈值和连续帧确认可抑制轻微抖动，无法保证任意分割错误都不影响时相。

四腔采用 **同一 LV ED/ES 帧**。例如心房在 LV ED 时的容积可以小于 LV ES 时的容积，
所以 `EDV_LA` 并不表示心房自身的最大容积，不能各腔各找最大值再混成一组结果。

首次有效配对前输出 `0xFFFFFFFF`。缺少某腔 ED 或 ES 掩膜时，该腔的两个结果都为未就绪；
缺少 LV 则无法配对。静态图和没有足够时相变化的片段不会凭空产生 ED/ES。
帧长错误或空 LV 会中断尚未完成的配对，但保留最近一次完整结果。
换病人/换序列时应复位此模块，避免跨视频配对。

## 接口与反压

- `in_data` → `out_data`，8 位灰度原样输出。
- `in_{LA,RA,LV,RV}_ctr/mask` → 对应的 `out_*`，八个标志原样输出。
- `in_eof/out_eof` 表示一帧最后一个像素，不是行尾。
- 仅在 `in_valid && in_ready` 时处理一个像素，坐标及统计不会在暂停期间前进。

一个弹性寄存器把像素、八个标志和 EOF 作为整体传递。
下游停止时输出的有效数据与标志保持，恢复后继续；计算流水线会排空已经接受的行，
不会重复计数。无反压时每拍接受一个像素，计算本身不增加帧间等待。
帧尾握手后 4 拍得到逐帧体积，下一拍供时相模块使用；确认时相还需要上述后续帧。

在 80 MHz 下，接收 65536 个像素的理想时间为 0.8192 ms；这只是模块吞吐估计，
不代表全系统帧率或已完成时序收敛。

当前 `top1.u_medical` 已接入医学分支：DDR 配准 → 完整 U-Net → 本模块 → 输出仲裁 → 双帧缓存。
像素及四腔掩膜/轮廓按握手传递；容积结果独立连接只读寄存器。U-Net 权重须先加载到 DDR。

## 只读寄存器与 PS 标定

读回路径：`medical_accel_top → top1 → top_threshold_demo → axi_lite_slave`。
PS 使用 `PL_REG_ADDRESS(index)`，基址 `0x44000000`。

| 结果 | WORD 编号 | 字节偏移 |
| --- | --- | --- |
| EDV_LA / ESV_LA | 0x10 / 0x11 | 0x40 / 0x44 |
| EDV_RA / ESV_RA | 0x12 / 0x13 | 0x48 / 0x4C |
| EDV_LV / ESV_LV | 0x14 / 0x15 | 0x50 / 0x54 |
| EDV_RV / ESV_RV | 0x16 / 0x17 | 0x58 / 0x5C |

例如 `158336` 表示 `1583.36 像素³`。PS 的 `R` 命令保留 `[PL rdbk]` 原始读回行。
写上述地址返回 `SLVERR`；已删除的 GLS WORD 0x18、0x19、0x28、0x29 读写均返回 `SLVERR`。
PS 用两次一致的八寄存器读取形成快照，换算容积并计算两个心室 EF。换算失败、未就绪、EDV=0
或 ESV>EDV 时返回 `0xffffffff`。EF 使用原始体积计算，避免先舍入 mL 的误差：
`EF_x100 = round((EDV_raw - ESV_raw) * 10000 / EDV_raw)`。
GUI/Python 只格式化 PS 结果，不重新计算 EF。

`csrc/MID_plt/src/config/pl_cmd.h` 的 `PL_VOLUME_ML_COEFF` 控制 PS 换算：

```text
V_mL = (寄存器值 / 100) × PL_VOLUME_ML_COEFF
等距像素 s mm：       系数 = s³ / 1000
当前圆盘模型 dx=dz=sx、dy=sy：系数 = sx² × sy / 1000
```

按用户指定，CAMUS 和 CardiacUDA 暂时共用项目已有的假设像素面积 `0.436280886141 mm²`。
假设等距正方形像素，边长 `0.6605156214208715 mm`，默认容积系数为
`0.00028817034062347113 mL/像素³`。这是估算尺度，未经过逐视频物理标定；不能把面积系数直接乘体积。
实际换算在 `common/medical_volume.h` 中完成，包含未就绪判断、舍入与溢出检查。
原始只读寄存器不变，PS 容积和 EF 都以整数放大 100 倍传输，GUI 显示两位小数。

`R` 追加 `[PS medical] NAME_ML_X100`、`EF_LV_X100`、`EF_RV_X100`、`FLAGS` 和
`COEFFICIENT_NANO`。连续流使用 TCP 元数据 v6：原 56 字节后追加 48 字节，依次为 flags、
系数×10^9、八个 mL×100、LV/RV EF×100，全部网络字节序，和图像共同计算 CRC。
Python 输出 `medical_volumes_ml`、`medical_ef_percent`、`medical_scale_assumed`；
未就绪为 `null`。旧 v4/v5 固件仍能回传图像，但没有新的医学数值。
图像模式在任务完成后读取 `R`；连续流每帧携带快照，不额外逐帧查询 UART，也不影响图像模式保存文件。
GUI 医学模式展示 LV/RV EDV、ESV、EF 和 LA/RA 在相同心室 ED/ES 时相的容积；
后两者不是独立检测心房最大/最小容积。没有完整周期时显示“—”，有结果后保持最近完整周期，随新结果更新。

系数应使用 **缩放后 256×256 图像**的间距。例如 800×600 等比缩放成 256×192 后补黑边，
有效间距为原始间距除以 0.32，黑边不属于解剖区域。
本地 CardiacUDA 364 个视频头均给出空间间距 1、1，360 个没有物理单位，4 个标为 mm；
没有得到可靠的真实标定，当前按用户指定沿用上述 CAMUS 假设尺度。部分原视频保留深度刻度，可后续逐段核实。

参考：[CardiacUDA 官方说明](https://github.com/XiaoweiXu/CardiacUDA-dataset)、
[ASE/EACVI 心腔定量指南](https://asecho.org/wp-content/uploads/2016/02/2015_ChamberQuantificationREV.pdf)。

## 本地验证

在仓库根目录运行，不综合、不访问开发板：

```bash
python scripts/tests/run_medical_checks.py
```

覆盖独立浮点参考的四掩膜体积、全尺寸数值范围、最后像素、短/长帧恢复、
两个不同心动周期、共享心房时相、缺失腔室、截断开头、平坦噪声、复位、
真实四掩膜流经算法到 8 个 AXI 寄存器读回，以及 PS 系数换算和 Python 协议。
测试证明计算和接口符合这版几何模型，不代表已用临床 EDV/ESV 真值验证。

### 真实标注检查

使用实际 CardiacUDA 逐帧标注，不修改数据集；需要 numpy、Pillow 和 Vivado XSim：

```bash
python rtl/heart_analysis/tests/run_real_annotation_checks.py --data E:/cardiarc_extract/cardiacUDC_dataset/label_all_frame
python rtl/heart_analysis/tests/report_annotation_checks.py --out build/tests/medical_real --camus-root E:/camus
```

验证脚本先填充源标注边界，再以最近邻等比缩放，保留逐帧参考与源文件位置。
非标准 5/6 类标签先单独排除，不猜测它们属于哪个腔。
8 段共 428 帧驱动 RTL 时相模块；normal-23-4 的 65 帧逐像素通过完整模块，
逐帧计算与参考逐位一致。自动候选时相缺少临床真值对照，不能据此声称医学准确。

合成矩形测试的 LV 宽度为 12/4 和 11/3，故 EF 为 88.89% 和 92.56%；
这是数学回归刺激，不是生理模型。真实序列测试发现并修正了局部波动产生额外配对的问题，
加入了三帧中值滤波和最短相位限制，并用真实曲线回归测试防止复发。

真实数据中仍有 82.59% 的代理 EF；方向敏感性比较也显示模型误差不能由标定系数解决。
当前模型没有长轴对齐，也没有双平面信息，仍需进一步验证。
CAMUS 的 gt_mask.bin 合并了非零类别，不适合作为单独 LV 腔掩膜；验证时只用 gt_label.bin 的类别 1。
500 对 CAMUS 人工 ED/ES 的离线模型比较保留在报告中，未将其包装成 RTL 或临床准确率验证。
